# 中文语音日记整理核对样例

`voice-cleanup-cases.json` 提供 12 个合成的短样例，用于人工比较提示词调整前后的整理效果。这些内容不来自私人日记，不依赖通讯录或常用词表。专有名词只使用同一录音内的上下文；无法确认的写法保留不确定性，交由用户核对。

每个样例包含：

- `id`：稳定的样例标识。
- `input`：待整理的语音转写文本。
- `exampleOutput`：一个可接受的整理示例，并非唯一标准答案。
- `mustPreserve`：人工逐项核对的事实、语气和限定条件。
- `checkNotes`：该样例需要留意的错误和允许的表达差异。

## 比较方式

1. 固定同一个模型、模型版本及采样设置，用完全相同的输入分别运行原提示词与候选提示词。若要比较模型，另开一轮并固定提示词，避免同时改变多个因素。
2. 将两版结果与原始输入并排查看，先逐项核对 `mustPreserve` 和 `checkNotes`，再比较断句、段落及阅读流畅度。重点检查否定、未确定的事情、数字、专名、条件和顺序。
3. 对每项记录“保留”“改变”“遗漏”或“新增”，并摘录出现问题的句子。任何事实反转、捏造或关键细节遗漏，都应优先于文风评价处理。
4. 对存在波动的样例按相同设置重复比较，记录模型和提示词版本。不要仅挑最顺畅的一次结果作结论。

整理目标是忠实地让原话更好读，不要求逐字保留无意义的填充词，也不要求与 `exampleOutput` 完全一致。中文数词与阿拉伯数字、合理的标点、少量自然表达差异都可接受；有意义的犹豫、情绪、未完句和细节应保留。只在原文明示枚举时考虑列表，不主动把日记改写成摘要或待办。

这些样例没有自动调用接口的脚本，也不构成模型质量的自动保证。JSON 格式检查或程序测试通过，只能证明文件与相关代码可用，不能证明真实模型会始终忠实整理。实际评价需要人工复核，长录音还应另外核对分段衔接与整篇细节保留情况。
