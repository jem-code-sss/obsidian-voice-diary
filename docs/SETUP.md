# 安装的软件与手机电脑同步

## 安装清单

| 使用位置 | 需要安装 | 用途 |
| --- | --- | --- |
| Windows x64 电脑 | [Obsidian](https://obsidian.md/download) 与 Voice Diary Processor | 接收录音、转写、保存成品，也可直接在电脑录音。 |
| 电脑的识别环境 | Python 3.10–3.12、SenseVoiceSmall INT8、sherpa-onnx、NumPy、imageio-ffmpeg | 仅电脑需要。可按 README 手动运行准备工具；FFmpeg 已随指定依赖提供，无需另装 Node.js 或显卡工具。 |
| 手机 | Obsidian 与 [Voice Diary Recorder](https://github.com/jem-code-sss/obsidian-voice-diary-recorder) | 只录音和保存；不用安装 Python、模型或 API 客户端。 |
| 手机与电脑之间 | Syncthing 或另一种可靠的仓库同步工具 | 将录音送到电脑，将成品送回手机。仅在一台电脑使用时不需要。 |
| 可选文字整理 | 自己选择的兼容文字 API | 不需要另装软件；应用接口配置并显式开启后才使用。未配置或关闭时只做本地识别。远程接口须 HTTPS，本机回环服务可用 HTTP。 |

Syncthing 是同步工具，不负责语音识别。可以用 Obsidian Sync 等工具代替它；不要让多套工具同时管理相同目录。

本教程对应 0.4.0。电脑端手动安装包与源码见 [Processor 0.4.0 Release](https://github.com/jem-code-sss/obsidian-voice-diary/releases/tag/0.4.0)，手机录音包见 [Recorder 0.4.0 Release](https://github.com/jem-code-sss/obsidian-voice-diary-recorder/releases/tag/0.4.0)。模型与依赖继续由用户在插件外手动准备，具体命令和资源见 [README](../README.zh-CN.md)。待办功能请将两端一并升级到 0.4.0 或更新版本。

## 可选配置文字 API

默认关闭即可完成本地转写。需要整理文字时，在「API 整理」填写完整地址、模型和该服务的 Key，再点击「应用接口配置」。远程服务只接受 HTTPS；本机回环服务可以使用 HTTP。编辑框是草稿，未应用的输入不会替换现用配置。

应用时须等待当前任务和接口请求结束。每次应用后 API 都关闭，确认地址与 Key 对应后再手动开启；连接测试仅在点击时发送简短测试文字。更换协议、主机或端口而仍沿用旧 Key 时，旧 Key 会被清除，请填新服务自己的 Key 并再次应用。Key 和任务文件以明文保存在仓库外，不要放进 Syncthing 等共享目录。

语音待办默认本地提取，即使日记 API 已开启，也不会自动使用接口。若希望用接口辅助待办提取，还需在「语音待办」开启相应 API 选项；该选项默认关闭。任一开关关闭或必要配置缺失时，待办使用本地规则。无需 API 账号即可测试完整的录音、提取和勾选流程。

## 用 Syncthing 配置

1. 电脑从 [Syncthing 官方下载页](https://syncthing.net/downloads/) 安装，按 [官方入门说明](https://docs.syncthing.net/intro/getting-started) 配对设备。手机需选择适合系统、仍在维护的兼容客户端；[旧官方 Android 应用已停止维护](https://github.com/syncthing/syncthing-android#discontinued)，不要把旧应用误认为当前官方安装推荐。iOS 用户可选择适合自己的仓库同步工具。
2. 两端各自用 Obsidian 打开准备同步的仓库，配置同一组共享文件夹。两端仓库的绝对磁盘路径可以不同；仓库内目录应一致。
3. 同步时包含 `Voice Diary/Recordings`、`Voice Diary/Notes` 和待办目录 `Voice Diary/Tasks`，采用双向读写。若共享整个仓库，也须确认音频、待办音频相邻的 `.voice.json` 时间清单和这些目录没有被忽略。仅同步音频会使待办等待时间信息。
4. 手机安装 Recorder、电脑安装 Processor。首次建议分别安装并启用，不依赖同步 `.obsidian` 目录分发插件；不要把 API 凭据、Python 环境或桌面设备数据放进共享目录。
5. 手机录音目录和电脑监听目录都设为 `Voice Diary/Recordings`。电脑的成品目录设为 `Voice Diary/Notes`，只在这一台电脑开启自动处理。
6. 手机保持前台录 10–20 秒，停止并回放。确认 Syncthing 显示同步完成后，等待电脑处理；插件会先观察录音稳定至少 30 秒。
7. 电脑按命名设置生成日记，例如 `12.13日记_出游.md`，包含可播放的源音频链接。等同步完成后，在手机打开成品并核对内容。
8. 再用独立「录制待办」入口说「明天买牛奶，下周整理照片」。确认音频及 `.voice.json` 都保存、同步完成，电脑生成待办笔记后，同步到手机勾选一项，再回电脑刷新查看其完成状态。

自定义目录也可以。升级用户继续使用原目录即可，别为了新默认路径移动历史录音或笔记。已有手机旧版目录可由 Recorder 的本机迁移保留；仍需手动确认电脑监听目录一致。

## 日记名称与凌晨录音

电脑「录音与路径」中的「成品笔记命名」默认采用 `MM.DD日记_主题.md`，也可改回「原音文件名 + transcript」；「标题包含年份」可生成 `2026.12.13日记_出游.md`。主题本地提取，不增加 API 调用；冲突加序号，不覆盖原笔记。此设置只影响新任务，已有文件和在途目标不改名。

日期按录音开始时刻划分：凌晨 04:00 前归前一日，04:00 起归当日。新录音的原文件名保存开始时间，跨过 04:00 才结束或延迟保存、重试、同步都沿用该时间。文件名只有日期而没有时间时不倒推一天。外来音频按文件创建时间处理，缺少创建时间时用处理时间；其创建时间可能受导入或同步影响。

待办不套用 04:00 规则，而按录音开始时真实当地日期解释「明天」「下周」。例如 11 月 7 日凌晨 03:59 的待办中，「明天」指 11 月 8 日。清单保存时间依据，电脑迟几天才收到录音也不会重算为收到当天。手机系统日期或时区设置不准确会影响记录的依据，录制前请确认系统时间；已经提取的事项可人工修改。完整规则、查看与确认方法见 [语音待办](VOICE-TODOS.md)。

## 常见情况

- 电脑没开机、Obsidian 没打开或自动处理暂停：录音可先保存，电脑恢复后再处理。
- 手机离线：先确保录音成功落盘，联网后等待同步。未保存的内存录音不能靠同步找回。
- 只同步了笔记：成品里的音频链接无法播放。请同时同步原始音频。
- 手机锁屏或切后台：当前配套插件会结束本段并尝试保存，返回前台需重新开始；这不是后台持续录音方案。
- 提示写入冲突或出现两份录音：失败写入留下的异常文件不会被覆盖，完整录音会以含完整 UUID 的新文件名另存。先确认另存文件能完整回放，再处理异常文件；尚未保存成功时保持应用打开并重试保存。
- 录音出现在电脑但未处理：检查路径、同步是否完成、自动处理是否开启，以及本地模型检查结果。
- 待办显示等待时间清单：检查音频旁 `.voice.json` 是否完整同步；不要手工填写日期或改指纹绕过校验。保留原文件，在录音设备重试保存或修复同步后等待重试。
- 手机勾选后电脑仍显示未完成：确认待办目录双向同步完成，再刷新查看界面。若出现冲突副本，打开各副本核对并保留正确内容，不在尚未同步完成时反复切换勾选。
- 播放列表或引用外部轨道的文件解码失败：只支持独立音频容器，请提供实际音频文件；不要只修改播放列表扩展名。
- 启动提示遗留 `device.guard`：先关闭所有 Obsidian 窗口，确认已无 Obsidian 进程，再备份并检查本机数据目录。只处理确认遗留的 guard，不要删除运行进程持有的锁或 guard；完整说明见 [隐私与本地数据](../PRIVACY.md)。
- 重新安装或换电脑：模型和凭据属于设备数据，需要在新电脑重新准备，不从手机同步。
