# 语音待办

0.4.0 增加独立的「录制待办」入口。手机或电脑录下计划，电脑用 SenseVoice 转写，再把明确事项存成可勾选的 Markdown 笔记。默认不使用文字 API，也不设置系统提醒或日历事件。

## 第一次使用

1. 将 Processor 和配套 Recorder 更新到 0.4.0 或更新版本。在电脑准备本地识别环境，只在这一台电脑开启自动处理。
2. 在电脑「语音待办」分区设置待办保存目录，默认 `Voice Diary/Tasks`。录音目录仍由「录音与路径」设置，默认 `Voice Diary/Recordings`；日记成品默认在 `Voice Diary/Notes`。三个位置可独立指定。
3. 使用手机时，把录音目录、日记目录和待办目录加入双向同步。录音目录里的音频与 `.voice.json` 都要同步，不能忽略后者。只用一台电脑时无需同步软件。
4. 点击清单图标或执行「录制待办：开始／停止」，说出事项，再次点击结束并保存。例如：「明天买牛奶。下周整理出游照片。」普通麦克风入口仍用于日记。
5. 等待电脑收到完整文件并处理，在「语音待办」分区或命令中打开明天、下周、待确认或全部未完成视图。核对原话，必要时修改日期或标题，再确认。
6. 完成后勾选事项。也可在手机直接打开同步回来的 Markdown 笔记勾选，再等同步完成并在电脑刷新。

手机须保持 Obsidian 前台。锁屏、切后台或设备中断时会结束本段并尝试保存，提示短暂显示；返回后需重新开始。未保存完成时请保持应用打开，退出或重载可能丢失内存音频。

## 日期如何理解

待办以**录音开始时当地的真实日期**为依据，保存后固定，不采用日记的凌晨 04:00 换日规则。

| 录音时间或原话 | 处理方式 |
| --- | --- |
| 2026 年 11 月 7 日 03:59 说「明天买牛奶」 | 待办日期是 11 月 8 日。同一时间录日记会归 11 月 6 日，两者规则独立。 |
| 2026 年 11 月 7 日说「下周整理照片」 | 保留 11 月 9 日周一至 11 月 15 日周日的范围，不把周日设为截止日。 |
| 2026 年 11 月 7 日说「下周三提交方案」 | 可确定为 11 月 11 日。 |
| 「周五交方案」「过几天预约」 | 日期有歧义，保留原话并交给你确认。 |
| 「是不是明天交方案？」 | 日期询问不能直接当作明天提交的承诺，需要确认。 |
| 「明天买牛奶，不，改后天」 | 同一段录音内结合改口处理；请核对最终日期和原话。 |
| 没有明确时刻 | 不擅自补上几点，也不创建提醒。 |

「明天」「下周」列表按**查看时电脑当前本地日期**筛选已保存日期，因此每天显示的范围会变化。录音里的相对日期已被固定，不会随迟到同步、重试、跨时区或查看日期变化而重新解释。

日期依据来自录音设备的系统时间。开始录制时的提示会显示日期；如设备日期或时区设置错误，应修正系统设置，并人工核对已经生成的事项。语音识别和提取都可能误解，重要日期请对照原音确认。

## 需要同步哪些文件

每次待办录音包括：

- `todo-….<音频扩展名>`：原始音频。
- `todo-….<音频扩展名>.voice.json`：同目录时间清单，记录真实录音时间、时区、随机录音身份和音频指纹。
- 电脑生成的待办笔记，例如 `2026.11.07待办_153000_a1b2c3d4.md`。

先核对完整音频，才写时间清单；两者保存、同步完整后电脑才处理。只收到音频、清单截断或音频指纹不匹配时，会显示等待，不按文件收到时间猜日期。这份时间信息不是 API Key，也不含转写正文，但仍属于个人录音数据。

同步、移动和备份时请保持音频与清单一起。不要手工改指纹或伪造时间清单来消除等待。音频或清单写入冲突时保留已有内容，完整录音会尝试另存；确认完整版本能够回放并已生成笔记后，再自行清理异常副本。

**处理前保留 `todo-` 文件名前缀及同名 `.voice.json`。** 如果未处理的录音同时被去掉前缀、删除清单，电脑将失去判断它是待办的依据，可能按普通外部录音生成日记。已完成且保留规范标记的待办笔记可用于恢复已有结果，人工勾选不因此重置。

首次开启自动处理会跳过已有文件；历史录音不自动转换成待办。普通录音继续走日记流程。待办录音应使用独立入口，使时间信息随录音一起生成。

## 查看、确认与完成

| 查看入口 | 内容 |
| --- | --- |
| 明天 | 日期或日期范围与明天相交的已确认、未完成事项。 |
| 下周 | 日期或日期范围与下周一至周日相交的已确认、未完成事项。 |
| 待确认 | 模糊、无法可靠校验或存在冲突的事项。 |
| 全部未完成 | 已确认的未完成事项，包括没有指定日期的事项。 |

一段录音生成一份待办笔记，保留每项原话、日期表达、确认状态、原音链接和完整转写。笔记中的标准 Markdown 勾选框是完成状态依据；视图读取它，不另建一套完成状态。无需安装第三方待办插件。

可以在查看界面修改标题、日期、范围与状态，确认或取消事项。也可直接编辑笔记：日期字段使用 `执行 YYYY-MM-DD`、`截止 YYYY-MM-DD`、`范围 YYYY-MM-DD ~ YYYY-MM-DD` 或 `未指定`。建议通过界面修改日期；手工编辑时请保留文件属性、事项定位标记和字段结构，否则可能无法被视图识别。取消的事项会保留证据，不作为活动待办。

视图保存前会检查事项是否已被同步或其他编辑修改。遇到变化时，请刷新后重新操作；不会直接用旧界面覆盖新内容。若同一事项出现内容不同的同步副本，会放入待确认并保留各版本，先打开原笔记核对，再通过你的同步工具处理冲突。已勾选或人工修改的笔记不会因为同一录音再次到达而自动重写。

手机 Recorder 提供录音入口，电脑 Processor 提供上述查看和确认界面；手机可直接编辑和勾选已同步的 Markdown 笔记。

## 本地规则与可选 API

默认流程是「本地识别 → 本地提取 → Markdown 笔记」。明确的中文动作、今天、明天、后天、下周及明确日期适合直接提取；模糊日期、引用、条件、否定和改口需要保守处理或人工确认。没有提取成事项的内容仍可在完整转写中检查。

单次提取最多处理 60,000 个字符、生成 80 个候选事项。超出范围时会限制提取并标记待确认，请对照完整转写补充。很长的录音建议按计划主题分段；本功能不能保证识别所有意图，也不会自动遍历历史日记补齐待办。

原始转写超过 500,000 个字符，或生成的待办笔记超过 1,000,000 个字符时，会停止保存待办笔记，保留原音和本机检查点。此时请按主题分段录制；不要反复重试同一份超长内容。

使用文字 API 必须同时满足：

1. 在「API 整理」应用完整接口、模型与 Key，并手动开启全局 API。
2. 在「语音待办」开启待办 API 选项；此选项默认关闭。

开启日记 API 不会自动允许待办请求。关掉任一开关或缺少必要配置时，待办使用本地规则。请求只发送当前录音的文字、录音当地日期与提取要求；不发送音频或时间清单，不读取通讯录、常用词或其他笔记。API 返回内容也会核对原话和日期；不符合结构时可退回本地提取，无法确认的内容进入待确认。关闭开关不能撤回已经发出的请求。

开启 API 不会自动改写既有待办笔记。其费用、可用性和数据保留规则由用户选择的服务决定。详细数据位置和清理说明见 [隐私说明](../PRIVACY.md)。

## 建议先做的检查

先保持两个 API 开关关闭，录一段含「明天」和「下周」的短计划。确认音频可回放、清单同步完整、待办目录正确，日期符合录制当天。再说一段含模糊日期或改口的内容，查看待确认和原话是否足够核对。最后勾选一项，等待同步到另一台设备，再刷新并重启确认状态保留。

自动化测试使用合成文字、音频及模拟宿主，不代替你的手机权限、同步配置、真实长录音或所选文字服务验收。验证范围见 [VALIDATION.md](../VALIDATION.md)。
